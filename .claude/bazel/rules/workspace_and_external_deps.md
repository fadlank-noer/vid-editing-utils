# Bazel WORKSPACE & External Dependencies

## Core Concepts

### Repository (Repo)
A directory tree with a boundary marker file at its root (`MODULE.bazel`, `REPO.bazel`, or legacy `WORKSPACE`/`WORKSPACE.bazel`). The repo where the current Bazel command runs is the **main repo**.

### Workspace
The environment shared by all Bazel commands from the same main repo. Encompasses the main repo + all defined external repos.

### Package
A directory containing a `BUILD` or `BUILD.bazel` file. Includes all files in its directory and subdirectories, **except** subdirectories that themselves contain a BUILD file (those become subpackages).

### Target
Defined in a package's BUILD file. Two principal kinds:
- **Files** — source files (checked in) or generated files (produced by rules)
- **Rules** — declare relationships between inputs and outputs. Inputs can be source files or outputs of other rules.

Invariant: files generated by a rule always belong to the same package as the rule itself.

## WORKSPACE File Functions

### 1. Project Identity & Root Marker
Presence of `WORKSPACE` (can be empty) marks the directory as workspace root.
```python
workspace(name = "my-project")
```

### 2. External Dependencies (Workspace Rules)

| Rule | Description |
|---|---|
| `http_archive` | Download and extract `.zip` / `.tar.gz` from a URL |
| `git_repository` | Depend on a Git repo (branch, tag, or commit) |
| `local_repository` | Depend on a local Bazel project (must have `WORKSPACE` + `BUILD`) |
| `new_local_repository` | Depend on a local non-Bazel directory (supply `BUILD` inline) |

```python
load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_archive")
http_archive(
    name = "foo",
    urls = ["https://example.com/foo.zip"],
    sha256 = "c9526390a7cd...",
)
```

### 3. `bind()` (Deprecated)
Creates aliases in `//external` package. Avoid in new projects.

### 4. Toolchain & Platform Registration
```python
register_toolchains("//my/toolchain:tc")
register_execution_platforms("//my/platform:linux_x64")
```

## Bzlmod (Replacement for WORKSPACE)

From Bazel 7+, **Bzlmod is the default**. WORKSPACE is scheduled for removal in Bazel 9.

### MODULE.bazel
```python
module(name = "my-module", version = "1.0")

bazel_dep(name = "rules_cc", version = "0.1.1")
bazel_dep(name = "platforms", version = "0.0.11")
```

### How Bzlmod Works
1. Starts from the **root module** (`MODULE.bazel` at project root)
2. Looks up all transitive deps in a **Bazel registry** (default: Bazel Central Registry)
3. Performs **MVS version resolution** (deterministic, minimizes diamond dependency conflicts)
4. Fetches repo sources (usually archives from the internet)
5. Module extensions can define additional repos via custom tags

### Bzlmod Benefits over WORKSPACE
- **Transitive deps automatic** — no need to re-declare transitive deps in every module
- **Strict visibility** — only direct dependencies are visible
- **Deterministic version resolution** — MVS algorithm
- **Language-ecosystem integration** — `rules_jvm_external` (Maven), `rules_python` (PyPi), `bazel-gazelle` (Go), `rules_rust` (Cargo)
- **Lockfile** support for reproducibility
- **`bazel mod` command** for dependency inspection

### WORKSPACE Shortcomings (Why Bzlmod Replaces It)
- WORKSPACE files of dependencies are **not evaluated** — all transitive deps must be in the main repo's WORKSPACE
- Workaround: "deps.bzl" pattern (macros defining multiple repos), but macros can't load other `.bzl` files
- Sequential evaluation + no version info in `http_archive` URLs = no reliable diamond dependency resolution

## Repository Naming

| Concept | Description | Label Syntax |
|---|---|---|
| **Canonical name** | Unique name within the workspace | `@@canonical_name//pkg:target` (double `@`) |
| **Apparent name** | "Nickname" for a repo in context of another repo | `@apparent_name//pkg:target` (single `@`) |
| **Main repo** | Always has empty string as canonical name | `//pkg:target` (no `@`) |

## Fetching
Repos are fetched on-demand. Use `bazel fetch` to pre-fetch. Use `--nofetch` for offline builds.

## REPO.bazel
Marks repo boundary (like WORKSPACE but for any repo). Can specify common attributes:
```python
repo(
    default_package_metadata = ["//:my_license"],
)
```

## Useful Commands
```bash
bazel mod graph          # inspect dependency graph
bazel fetch //...        # pre-fetch all deps
bazel build --nofetch    # offline build (fails if deps missing)
```
